# Product

## Register

brand

## Users

Drei Zielgruppen in dieser Reihenfolge: (1) Entwickler und Data Scientists, die die API oder den MCP-Server anbinden wollen und schnell zu Endpunkt, Beispiel-Response und Lizenz müssen. (2) KI-Agenten und LLM-Crawler (llms.txt, MCP-Kataloge), die die Site maschinell lesen. (3) Verwaltungs- und Presse-Kontakte (Dataport, Kommunen, Journalisten), die prüfen, ob InfraNode seriös und nutzbar ist.

## Product Purpose

Die docs-site ist das öffentliche Schaufenster von InfraNode: Landingpage, SEO-Themenseiten (daten/*), API-Referenz, MCP-Doku, Changelog, Abdeckungsübersicht. Sie muss zwei Dinge gleichzeitig leisten: Entwickler in unter einer Minute zum ersten erfolgreichen Request bringen und institutionellen Besuchern Vertrauenswürdigkeit signalisieren. Erfolg = API-Anbindungen, MCP-Installationen, eingehende Kooperationsanfragen.

## Brand Personality

Amtlich-solide, entwickler-pragmatisch, civic-tech-offen. Vertrauenswürdig wie eine gute Behörde, aber modern; schnell zum Code wie Stripe-Doku; zugänglich und gemeinwohlorientiert wie die Open-Data-Community. Ton: präzise, unaufgeregt, deutsch-zuerst mit englischem Zwilling.

## Anti-references

- Startup-SaaS-Look: keine Gradient-Heros, keine Pricing-Table-Ästhetik, kein Growth-Marketing-Gefühl.
- Behörden-Staub: nicht wie govdata.de oder klassische Verwaltungsportale wirken, nicht altbacken, nicht überladen.
- KI-generiert wirkend: keine austauschbare Template-Ästhetik, kein Baukasten-Eindruck.

## Design Principles

1. Code zuerst: jede Seite, die einen Endpunkt beschreibt, zeigt innerhalb des ersten Viewports einen kopierbaren Request.
2. Vertrauen durch Präzision: Lizenzen, Quellen und Stände sind sichtbar, nie versteckt; das ist das Differenzierungsmerkmal gegenüber Aggregatoren.
3. Ruhe statt Show: Petrol/Grün aus dem Logo, viel Weißraum, dunkle Codeblöcke als dunkelste Fläche. Hell ist der Standard; Dark Mode folgt der Systempräferenz als reine Token-Schicht mit derselben Ruhe (kein Toggle, keine zweite Identität).
4. Barrierefreiheit ist Werbeversprechen: der Footer wirbt damit, also muss WCAG AA nachweisbar gehalten werden.
5. Maschinenlesbarkeit ist gleichberechtigt: llms.txt, OpenAPI, JSON-LD und saubere Semantik sind Teil des Designs, nicht Anhang.

## Accessibility & Inclusion

WCAG AA als verbindliches Ziel (wird im Footer beworben). Tastatur-Navigation mit Skip-Link vorhanden und muss erhalten bleiben. Kontraste der Markenfarben sind auf Weiß AA-justiert. Reduced-Motion berücksichtigen, Touch-Ziele auf Mobil mindestens 44px.
